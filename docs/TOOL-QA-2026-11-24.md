# imagec 全部 24 项工具实测

2026-11-24 · 当前项目本地预览 · Windows Microsoft Edge / Playwright · 1440×900 和 375×812 CSS 视口

两种视口都运行了 24 个工具的基本工作流。上传类工具使用真实文件输入，导出后读取字节、解码图像、检查尺寸和部分像素，或解包 ZIP 并核对内容。另运行了仓库现有的 `npm run qa:local`，其中 24 个工具路由、移动端标题、裁剪预设及圆形透明、压缩目标字节、批量缩放及坏文件处理均通过。375px 下实测页面无整页横向溢出。

## 已复现问题

| 优先级 | 工具 | 操作与实际结果 |
| --- | --- | --- |
| P1 | 格式转换 | 上传 PNG 后切换到 JPG、WebP、BMP，立即点击下载。三个文件都可能沿用上一次编码的 PNG 字节，文件名却采用新后缀。等约 500ms 再下载，三种格式的文件头正常。设置变更到完成编码之间，下载仍可点击。 |
| P1 | 格式转换 · AVIF | 上传 PNG，选 AVIF，等待 500ms 后下载。文件名为 `source.avif`，文件头仍是 `89 50 4E 47`（PNG），页面未报告编码失败。浏览器回退输出时，页面只判断 Blob 是否存在，没有校验实际 MIME。 |
| P1 | 旋转翻转 | 上传 1600×1000 图片，等首次导出就绪，点击 90° 并立即下载。界面显示 1000×1600，首次下载实际仍为 1600×1000，等待 350ms 后再下载才正确。 |
| P1 | 清除元数据、HEIC 转换 | 等首次导出就绪再切换格式并立即下载。清除元数据从 PNG 切到 JPG，得到后缀为 JPG 的 PNG。HEIC 从 JPG 切到 PNG，得到后缀为 PNG 的 JPEG。等待 500ms 后格式正确。 |
| P1 | 裁剪 · 初始选区 | 上传 1600×1000 图，选区默认占满全图。在画面内部从约 (30%, 40%) 拖到 (65%, 70%)，375px 视口下选区变成 1040×700，且从新位置延伸至右下边界。按拖动轨迹框选应约为 560×300。实现命中「移动」后，越界处理把选区尺寸裁掉了。用户无法用这次直觉拖动得到目标选区。 |
| P1 | 裁剪 · 更换失败后导出 | 成功裁剪 `source.png`，再选择内容无效的 `broken.png`。随后下载得到上一张图的裁剪内容，文件名却是 `broken.png`。 |
| P1 | 全站上传入口 · 键盘 | 检查 22 个带文件输入的工具。文件输入与上传区域均未提供可用的 Tab 焦点入口。SVG 优化仍可通过粘贴源码操作。另有 2 个纯文字输入工具无需上传。 |
| P2 | 裁剪 · 预设状态 | 选择一寸，再选「与选区相同」。宽度保持 714px，比例按钮没有选中项，原 295:413 比例仍锁定。将宽度改为 500px，导出 500×700。页面没有显示这把锁来自哪个比例，也没有区分「解除输出尺寸」与「解除比例」。 |
| P2 | 裁剪 · 尺寸可发现性 | 预设列表只写 Instagram、社媒封面、缩略图等。选择前看不到实际像素。选区数字显示原图取样尺寸，选择一寸时界面可能显示 714×1000，实际下载是 295×413。 |
| P2 | 水印 · 旋转控制 | 加黑色文字水印，保持平铺关闭，从 0° 调到 35°。两次下载字节完全相同。文字与图片的单点绘制路径均没有应用旋转。 |
| P2 | 水印 · 空白输入 | 代码在文字框为空时实际绘制英文 `Watermark`。默认白色水印在白底样图中看不出来，用户清空输入时仍可能导出带占位文字的图片。 |
| P2 | 格式转换、批量处理 · 键盘 | 格式卡片使用只监听点击的 div。格式转换的 5 个格式选项、批量处理的 4 个转换格式选项均无法通过 Tab 选取。 |

文件格式错配建议先统一按「当前设置 + 已完成的编码结果」管理下载状态，并校验输出 MIME。裁剪建议先解决上传后的第一次拖动，再统一几何选区、比例和最终输出尺寸的显示。
